# Benchmark reports

The measured sections are generated by the harness after **two real live runs** on the Intel Mac:

```bash
dotnet run --project benchmarks/Issue8.NluBenchmark -- report --runs v3-run1,v3-run2
```

Expected files, both committed as the Issue #8 evidence:

```text
reports/<model-slug>-intel-mac.md
reports/<model-slug>-intel-mac.json
```

Each report contains the model tag, environment metadata, dataset/schema/prompt versions and
hashes, both run summaries, the combined metrics, every docs/PLAN.md section 13.3 gate with its
measured value, representative mismatches and the Issue #9 model recommendation.

The report command refuses dry-run artifacts, so this directory can never contain fixture
numbers presented as benchmark evidence.

## Version of record

`qwen3.5-2b-q4_k_m-intel-mac.{md,json}` is the Issue #8 version of record. After the generated
sections it carries a curated `Issue #8 final outcome` block (`issue8Outcome` in the JSON) that
records the final prompt-v3 two-run evidence, the required representative inspection of the
hard-budget and follow-up-reference cases, the blocked optional 4B warm-up attempt, the candidate
that was deliberately not tested, and the conclusion handed to Issue #9.

That curated block is derived only from the raw artifacts named inside it
(`results/v3-run1.json`, `results/v3-run2.json`) and the recorded 4B warm-up output; it adds no
measurement and changes no gate. Re-running the `report` command regenerates the measured sections
and drops the curated block, so regenerate from the same artifacts only if the block is restored
afterwards.
